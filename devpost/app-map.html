PostReady Studio

One product photo becomes a styled advertisement with editable Amharic or English words and an independent social caption.

How the pieces connect

Photo + details
Next.js→ Validate + generate
FastAPI → Gemini→ Edit + preview
Browser canvas→ Download PNG

Next.js and FastAPI run with PostgreSQL, MinIO, Redis, Celery worker and beat. Accounts and business profiles persist in PostgreSQL. Generated ads and editable revisions persist privately for seven days, with image assets in MinIO. Saving edits preserves the original deadline. Gemini receives the photo and relevant generation content. The API key remains on the backend.

Reference route: edit a headline

This is a reference route through the finished code.

  1. frontend/components/ResultEditor.tsx — ResultEditor: the headline field updates image text; the social-caption field updates a separate value.
  2. frontend/app/page.tsx — Page: owns the result state and supplies setResult to the editor.
  3. frontend/lib/render-ad.ts — renderAd: draws artwork and current text. The editor copies the finished render into the visible canvas, and download exports it as PNG.

To change this, start here

  • Theme samples and exact colors: frontend/lib/themes.ts and DetailsForm.tsx.
  • AI artwork direction: backend/app/gemini.py, THEME_DIRECTIONS and artwork_prompt.
  • Text placement and fitting: frontend/lib/render-ad.ts, text.
  • Price rules: frontend/lib/validation.ts, validate, and backend/app/schemas.py, Details.

A practice to reuse

Turn a broad preference into observable behavior. The approved theme requirement in devpost/prd.md became three presets: fixed artwork instructions plus exact canvas colors. backend/tests/test_validation.py, test_theme_contract, checks the allowed choices and prompt direction; live generation checks the visual result. Separate creative AI output from deterministic controls, then verify each part.

Editing checks compared the artwork region before and after text changes, inspected English and Amharic PNG downloads, and confirmed social-caption changes left the preview unchanged. Those observations test the user promise rather than only checking that code runs.

Accounts, saved ads and publishing

  • backend/app/accounts.py handles account sessions and reusable business profiles; logos.py handles private logos.
  • backend/app/ads.py enforces ownership, stores revisions, serves compact thumbnails and removes expired ads. Profile logos are retained independently.
  • frontend/components/AdLibrary.tsx shows recent-ad previews; ResultEditor.tsx saves editable revisions and PNGs.
  • SocialConnection.tsx and backend/app/telegram.py link a channel using private identity and channel proofs. One application bot serves business owners; its token stays on the server.
  • PublishPanel.tsx previews the saved revision and requires explicit publication. Telegram attempts persist in PostgreSQL. Duplicate submissions reuse the existing attempt; uncertain outcomes are never automatically resent.
  • backend/app/worker.py schedules Telegram update polling, queued publication and expired-ad cleanup through Celery and Redis. telegram_api.py calls Telegram without logging token-bearing URLs.

Migrations in backend/migrations/versions/ define the persistent tables. Run backend tests with docker compose exec api python -m unittest discover -s tests.

Run again

Set your key in the ignored local .env, then run docker compose up --build. Open localhost:3010.
